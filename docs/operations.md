# 운영과 초기 설정

현재 2단계 DB 기반까지 구현했습니다. 실제 클라우드 프로젝트·Pages 배포·운영 백업은 아직 연결하지 않았습니다.

## 최초 운영자

최초 가입자를 자동으로 운영자로 지정하지 않습니다. 첫 초대는 운영자가 없을 때에도 **신뢰할 수 있는 DB 소유자 연결**에서 발급할 수 있습니다. 브라우저·일반 API·service_role에는 bootstrap 실행 권한을 주지 않습니다.

1. Supabase SQL Editor 또는 관리용 SQL 연결에서 `select private.issue_bootstrap_invite();`를 실행합니다. 무작위 코드는 이 결과에서만 보여주고 DB에는 SHA-256 해시만 저장합니다. 원문을 URL, 소스, 로그에 남기지 않고 대상 사용자에게 전달합니다. 기본 1회용·7일이며 사용 가능한 초기 코드가 이미 있으면 중복 발급을 거부합니다.
2. 대상 계정이 이메일 인증과 해당 코드로 정상 초대 가입을 완료해야 합니다. **현재 가입·코드 사용 RPC는 3단계 구현 예정**이므로 지금 운영 환경에서 가입을 끝낼 수 있는 상태는 아닙니다. 테스트에서는 로컬 전용 픽스처로 이 조건을 구성합니다.
3. 관리용 SQL 연결에서 `select private.bootstrap_admin('인증과_가입을_마친_계정_UUID'::uuid);`를 실행합니다. 이메일 인증·활성 회원·초대 사용 기록을 모두 검증하고 운영 기록을 남깁니다.
4. 활성 운영자가 이미 있으면 bootstrap은 실패합니다. 이후 운영자 추가·회수는 `change_member_role`을 사용합니다. 마지막 운영자를 없애는 변경은 막습니다.

실행 예시는 `supabase/admin/bootstrap.sql`에도 주석으로 제공하며 파일을 그대로 실행해도 계정을 변경하지 않습니다. 만료·분실한 초기 코드는 DB 소유자가 해당 코드 ID를 확인해 `revoked_at`을 설정한 뒤 새로 발급합니다. 해시에서 원문을 복구하거나 회원 가입 조건을 수동으로 우회하지 않습니다.

## 무료 요금제 기준

2026-10-19 확인 기준 Free는 DB 500 MB, Storage 1 GB, 월 일반/캐시 전송량 각각 5 GB, 월 활성 사용자 50,000명, Edge Functions 월 500,000회입니다. 실제 한도는 배포 전에 [공식 요금표](https://supabase.com/pricing)에서 다시 확인합니다.

이번 단계는 PostgreSQL·Auth·RLS·비공개 Storage만 사용합니다. 유료 이미지 변환, 벡터/분석 버킷, PITR, 유료 확장 기능에 의존하지 않습니다. 로컬에서는 유료 한도가 자동으로 시뮬레이션되지 않으며 클라우드 사용량은 대시보드에서 관리해야 합니다.

- 무료 프로젝트의 비활동 일시 중지와 자동 백업 미포함을 운영 조건에 반영합니다.
- 3단계의 실제 가입 메일은 외부 SMTP를 설정합니다. Supabase 기본 메일 발송은 팀 주소 대상 테스트용입니다. SMTP와 발신 도메인 비용은 공급자 조건을 별도로 확인하며, 이번 단계에서는 연결하지 않습니다.
- 5단계 이미지 처리에서 무료 플랜의 유료 이미지 변환 API를 사용하지 않고 서버 검증·압축을 구현합니다. 사진·과거 프로필 보존으로 Storage가 누적되므로 사용량을 관리합니다.
- 무료 한도 초과 시 자동 유료 업그레이드를 수행하지 않습니다.

## 후속 운영 작업

5단계에서 이미지 변환 후 저장 한도, 임시 자산 정리 주기와 참조 보호를 정합니다. 8단계에서 DB와 Storage 별도 백업·복원 절차, 외부 저장소 연결과 실제 복원 검증을 완성합니다. 회원 PDF/JSON 내보내기는 서비스 복구용 백업을 대체하지 않습니다.
