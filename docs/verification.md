검증일: 2026-10-19 (Asia/Seoul)

## 통과한 항목

| 항목 | 실행 및 결과 |
| --- | --- |
| 잠금 파일 설치 | `pnpm install --frozen-lockfile` 성공 |
| 의존성 호환 | `pnpm peers check` — 문제 없음 |
| TypeScript | `pnpm typecheck` (`pnpm check`에 포함) 성공 |
| 린트 | `pnpm lint` — 경고·오류 없음 |
| 프로덕션 빌드 | `pnpm build` — Vite 8.3.4, `dist/` 생성 |
| 개발 서버 | `pnpm dev --port 5173 --strictPort` 실행 및 앱 내 브라우저 확인 |
| E2E | `PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e` — 6개 통과 |
| 환경 파일 제외 | `git check-ignore`로 `.env.local`, `.env.production`, `node_modules`, `dist` 제외 확인 |

E2E는 실제 프로덕션 빌드의 `/mini-commu/` 경로에서 3개 시나리오를 데스크톱과 Pixel 7 화면 크기로 각각 실행했습니다.

1. Supabase 미설정 안내, 캐릭터 경로 이동과 본문 포커스, 시작 화면 복귀, 가로 넘침 없음, 브라우저 런타임 오류 없음.
2. `#/login`, `#/posts/example`, `#/auth/callback` 직접 접속 및 새로고침 후 같은 화면 유지.
3. 없는 경로에서 404 안내와 시작 화면 복귀.

검증 환경: macOS, Node 24.19.0, pnpm 11.25.0, 로컬 Google Chrome. 네트워크 설치와 로컬 서버 실행은 도구의 승인된 접근으로 진행했습니다.

## 확인 과정에서 수정한 항목

- 최신 TypeScript 7은 typescript-eslint 지원 범위 밖이어서 TypeScript 6.0.3으로 고정했습니다. 최종 설치에는 peer dependency 문제가 없습니다.
- E2E의 브라우저 콜백 타입 검사를 위해 테스트 설정에 DOM 라이브러리를 포함했습니다.

## 미실행 및 후속 검증

- A24 중 타입 검사·린트·빌드·로컬 하위 경로 라우팅을 확인했습니다. 실제 GitHub Pages 배포 경로 검증은 아직 수행하지 않았습니다.
- GitHub Actions는 최초 푸시 시 실행하도록 구성했습니다. 이 기록의 결과는 로컬 실행 기준입니다.
- Supabase 외부 프로젝트 및 로컬 DB는 연결하지 않았습니다. 스키마·RLS가 없는 1단계이므로 데이터 흐름 검증은 2단계부터 진행합니다.
- 인증, 이메일 콜백의 실제 토큰 처리, 비밀번호 재설정, 세션 지속, 권한, 동시성, CRUD, 이미지, 내보내기는 아직 구현하거나 검증하지 않았습니다.
- 모바일 검증은 화면 크기 에뮬레이션입니다. 실제 기기 및 Safari 검증은 후속 단계에서 진행합니다.
- 실제 배포, 운영 백업 및 외부 저장소 연결은 수행하지 않았습니다.

# 2단계 검증 기록

검증일: 2026-10-19 (Asia/Seoul). Supabase CLI 2.121.0 native 런타임의 실제 로컬 PostgreSQL 17·Auth·PostgREST·Storage를 사용했습니다. 클라우드 프로젝트는 연결하지 않았습니다.

| 항목 | 결과 |
| --- | --- |
| `pnpm db:reset` | 빈 로컬 DB에 4개 마이그레이션 순차 적용 성공 |
| `node scripts/supabase.mjs db lint --local --level warning` | 스키마/함수 오류 없음 |
| `pnpm db:test` | 실제 DB/API 테스트 17개 통과 |
| `pnpm db:types:check` | 생성 타입과 실제 public 스키마 일치 |
| `pnpm install --frozen-lockfile` / `pnpm peers check` | 설치 성공 / 호환 문제 없음 |
| `pnpm check` | 타입 검사·린트·프로덕션 빌드 성공 |
| `PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e` | 기존 데스크톱·모바일 E2E 6개 통과 |

권한 테스트는 일반 회원 2명, 운영자 2명, 미가입 Auth 계정, 이용 정지 계정, 이메일 미인증 계정을 구분했습니다. 준비에만 관리 권한을 쓰고 각 검증은 해당 역할·JWT로 실행합니다.

- RLS와 고정된 SECURITY DEFINER search_path, public/private 경계 및 컬럼 노출 확인.
- 미가입·정지 계정의 정상 콘텐츠 조회 차단, 비로그인 접근 거부.
- 일반 회원과 운영자 모두 직접 테이블 쓰기·내부 소유 정보·초대 해시·투표 원시 데이터 조회 거부.
- 실제 이메일/비밀번호 로그인으로 얻은 계정별 JWT의 PostgREST 조회·변조 요청 차단 확인.
- 비공개 Storage에 실제 파일을 넣고 활성 회원의 다운로드 성공, 미가입·정지·비로그인 및 숨김 전용 이미지 다운로드 거부, 일반 회원 업로드 거부 확인.
- 마지막 운영자의 강등·정지·삭제 차단. 두 운영자의 동시 자기 강등 및 동시 자기 정지 중 하나만 성공.
- 운영자 권한 회수 트랜잭션과 대기 중 요청을 실제 DB 잠금으로 겹치게 만들어, 잠금 해제 뒤 회수된 운영자의 요청이 거부됨을 확인.
- 회원 역할 변경·이용 정지와 운영 기록의 호출자 ID 확인.
- 초기 코드 원문 미저장, 인증·초대 이력 없는 운영자 지정 차단, 일반 사용자 및 service_role의 bootstrap 실행 차단.
- 이름·제목 길이, 이미지 위치 한도, 투표 계정 중복, 다른 투표 선택지 연결, 답글 깊이/부모 글 불일치, 스냅샷 변경 및 참조 자산·캐릭터 삭제 차단.

테스트 계정·콘텐츠·Storage 파일은 실행 후 정리했습니다. 최초 운영자의 가입 전제는 **로컬 테스트 픽스처로 구성**했으며 실제 초대 가입 전체 흐름은 3단계 검증 대상입니다.

A03은 현재 DB·Storage 경로, A05는 서버 권한 변경, A09/A16은 내부 정보 비노출 부분을 확인했습니다. 아직 없는 내보내기·캐릭터 쓰기·투표 결과 API까지 통과했다고 간주하지 않습니다. 기능별 검증은 해당 구현 단계에서 추가합니다.

무료 플랜 사용량 제한은 로컬 실행 환경에서 자동 적용되지 않습니다. 실제 클라우드 연결, 무료 한도 내 부하 검증, SMTP 메일 발송, Pages 배포, 운영 백업·복원은 미실행입니다. CI는 푸시 후 프런트엔드와 별도의 DB 작업을 실행하도록 추가했습니다.
