# 6단계: 투표와 커뮤니티 운영

6단계는 기존 Supabase Auth·PostgreSQL·비공개 Storage에 추가 RPC와 화면을 연결합니다. 유료 서비스나 새 서버는 추가하지 않습니다. 새 마이그레이션을 먼저 적용하고 프런트엔드를 갱신합니다. 실제 클라우드 프로젝트와 Pages 배포는 아직 수행하지 않았습니다.

## 투표

새 글에서 형식을 `투표글`로 선택합니다. 질문 1~100자, 선택지 2~10개(각 1~100자), 단일/복수 선택, 익명/기명, 재투표, 결과 공개 시점, 선택적 마감을 지정합니다. 기본은 단일·익명·재투표 불가·참여 후 공개·마감 없음입니다. 제목/본문/첨부와 함께 원자적으로 생성하며 요청 UUID 재시도로 글을 중복 생성하지 않습니다. 투표 설정도 기기별 초안과 미리보기에 포함합니다.

작성자는 상세 화면에서 첫 참여 전까지 투표 설정을 수정할 수 있습니다. 첫 참여가 생긴 뒤 질문·선택지·모든 설정을 고정합니다. 제목·본문·첨부는 계속 수정할 수 있습니다. 작성자와 운영자는 조기 마감할 수 있으며 마감 취소는 제공하지 않습니다. 예정 마감은 서버 시각으로 판정하고, 화면의 주기 갱신보다 늦게 표시되더라도 서버가 마감 후 참여를 거절합니다. 입력 시각은 기기 시간대, 표시 시각은 Asia/Seoul 기준입니다.

`submit_vote`는 회원 행과 해당 게시글 행을 잠근 뒤 마감·선택지·계정별 참여를 검사합니다. 두 캐릭터나 두 창에서 동시에 참여해도 `(poll_id,user_id)` 한 건만 생성합니다. 재투표는 같은 참여 행의 선택지 집합을 한 트랜잭션에서 교체합니다. 기명 참여의 이름과 이미지는 최초 참여 캐릭터 스냅샷으로 보존합니다. 익명 참여 행에는 캐릭터·이름·이미지를 저장하지 않습니다.

원시 참여/선택지는 `private` 스키마에만 존재합니다. `get_poll`은 본인의 선택지와 권한별 결과만 반환합니다. `always`는 모든 활성 회원, `after_vote`는 본인이 참여한 경우, `after_close`는 마감된 경우 결과를 반환합니다. 참여 후 공개 정책은 마감 후에도 비참여자에게 결과를 공개하지 않습니다. 결과 공개 전에는 참여 수와 득표 수가 `null`, 기명 목록은 빈 배열입니다. 운영자도 같은 결과 정책을 따릅니다. 익명 참여자의 계정·캐릭터는 운영 화면과 일반 API로 조회할 수 없습니다.

기명 목록에도 내부 계정/참여 ID는 반환하지 않습니다. 득표 비율의 분모는 참여 계정 수이며 복수 선택 합계는 100%를 넘을 수 있습니다. 과거 기명 참여 이미지도 정리 대상에서 제외하고, 유효한 공개 결과에서만 스냅샷 참조로 읽을 수 있습니다.

## 탐색과 내 활동

피드에 카테고리·글 형식·공지 필터와 제목/본문 부분 검색을 제공합니다. 검색 문자열의 `%`, `_`, 역슬래시는 패턴 문자가 아닌 문자 그대로 처리합니다. `pg_trgm` GIN 인덱스를 제목+본문 소문자 표현식에 적용했습니다. 짧은 검색어는 인덱스 효과가 제한될 수 있으며 대규모 데이터 성능은 운영 데이터로 별도 측정해야 합니다.

작성자 이름을 누르면 해당 캐릭터의 글을 봅니다. `/activity`는 현재 선택 캐릭터와 관계없이 계정 소유의 글/댓글을 조회하며 캐릭터로 필터링할 수 있습니다. 삭제한 캐릭터라도 열람 가능한 과거 활동이 남아 있으면 당시 이름으로 필터에 표시합니다. 삭제·숨김 글이나 해당 글의 댓글은 검색과 내 활동에서 제외합니다.

`browse_posts`는 고정 여부, 고정 순서, 등록 시각 내림차순, UUID 내림차순을 커서에 담아 20개씩 조회합니다. 전체 피드 고정은 전체 목록에서, 카테고리 고정은 해당 카테고리 목록에서 적용합니다. 각 글을 한 목록에서 한 번만 반환하며 고정과 일반 목록을 따로 합치지 않습니다. 목록 갱신 시 이미 불러온 페이지도 처음부터 다시 조회해 숨긴 글과 바뀐 정렬을 반영합니다. 여러 요청 사이의 동시 변경을 고정하는 스냅샷 세션은 사용하지 않습니다.

## 운영 화면

`/admin`은 활성 운영자 전용이며 서버도 각각 권한을 검사합니다.

- 초대: 기본 7일·1회 코드 발급, 만료/사용 한도 변경, 폐기. 원본 코드는 발급 응답에서만 한 번 표시하고 브라우저 영구 저장소에는 저장하지 않습니다. 최근 100개 목록을 제공합니다.
- 회원: 이메일·역할·이용 상태를 운영자 전용 API로 조회합니다. 사유를 입력해 운영자 지정/해제와 이용 정지/재개를 적용합니다. 마지막 활성 운영자를 잃는 변경은 동시 요청에서도 차단합니다.
- 공지/고정: 각 게시글에서 별도로 지정·해제하고 전체/카테고리 고정과 순서를 설정합니다. 변경 사유를 기록합니다.
- 콘텐츠: 글과 댓글을 사유와 함께 숨기거나 운영자 삭제할 수 있습니다. 숨김은 해제 가능하지만 작성자 삭제와 운영자 삭제는 복구할 수 없습니다. 운영자가 타인 본문을 편집하는 기능은 없습니다.
- 숨김/삭제 관리: 대상 ID·상태·수정 시각만 표시합니다. 숨긴 본문이나 삭제 본문을 일반 상세 조회로 열지 않습니다.
- 조치 기록: 실행자, 대상 회원 또는 콘텐츠 ID, 조치, 사유, 시각을 20개씩 조회합니다. 회원·숨김 목록도 커서로 추가 조회합니다.

회원 계정 ID와 이메일은 회원/기록 관리에 필요한 운영자 전용 응답에만 포함합니다. 일반 피드·댓글·투표·내 활동에는 계정 소유 ID를 반환하지 않습니다. 권한 변경과 운영 조치는 같은 운영자 가드 잠금 순서를 사용해 권한 회수와 경합할 때 다시 검사합니다. 공지·콘텐츠·투표 설정은 버전 충돌을 감지합니다.

다음 7단계는 열람 가능한 콘텐츠의 PDF/JSON/이미지 내보내기입니다. 6단계에서는 내보내기를 구현하거나 클라우드 백업을 실행하지 않았습니다.
