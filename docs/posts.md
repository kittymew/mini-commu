# 5단계: 게시글·카테고리·첨부·댓글

일반글 작성/미리보기/수정/삭제, 최신 피드와 카테고리 필터, 이미지 4장과 순서 변경/확대, 댓글과 1단계 답글을 실제 DB에 연결했습니다. 투표·공지/고정·검색·내 활동·일반 운영 화면은 6단계입니다. 카테고리 관리만 이번 단계에 `/categories`로 제공합니다.

## 본문과 작성

본문은 닫힌 JSON 문법입니다. 문서에는 최대 100개의 `paragraph`, `bullet`, `ordered` 블록이 있고 각 블록에는 `text` 노드와 선택적인 `bold`, `italic`, `link` 서식만 허용합니다. 링크는 http/https만 허용합니다. 임의 HTML, 이미지 노드, data/javascript 링크, 알 수 없는 필드를 서버가 거부합니다. 본문의 HTML처럼 보이는 문자열은 React 텍스트로 표시합니다. 편집기에 붙여넣는 이미지 파일은 막고 별도 첨부 영역을 사용합니다.

편집기에서 문단을 추가하고, 글자를 선택한 다음 굵게/기울임/링크를 적용합니다. 문단별로 본문·글머리 목록·번호 목록을 선택합니다. 제목은 1~100자, 본문은 5,000자, 댓글은 1~1,000자를 Unicode 코드 포인트로 셉니다. 줄바꿈은 LF로 정규화합니다. 서버 `private.document_text`가 문법을 검증하고 검색용 평문을 생성합니다. 클라이언트가 평문이나 작성자 이름을 지정하지 않습니다.

새 글은 작성 화면에서 선택한 캐릭터 ID를 보내며 기존 스냅샷 트리거가 실제 소유/활성 상태와 이름/이미지를 확인합니다. 수정/삭제는 비공개 계정 소유 관계를 사용하므로 캐릭터를 바꾸거나 삭제한 뒤에도 본인 글을 관리할 수 있습니다. 글 형식/ID/작성자 스냅샷은 불변입니다. 운영자도 타인의 본문을 수정할 수 없고 카테고리만 별도 함수로 옮깁니다.

`create_post`/`create_comment`의 요청 UUID는 ID이자 재시도 키입니다. 같은 계정의 중복 요청은 같은 결과를 반환합니다. 수정에는 기대 버전이 필요하며 충돌 시 덮어쓰지 않습니다. 화면은 입력을 남기고 명시적으로 최신 내용을 다시 불러오게 합니다. 미리보기에서 제목·본문·카테고리·작성 캐릭터·이미지를 확인할 수 있습니다.

## 초안과 조회

새 글 초안은 `mini-commu:draft:<계정 ID>:new`에 입력 후 0.5초 간격으로 저장합니다. 제목, 문서, 카테고리, 이미 처리된 이미지 ID, 요청 UUID와 저장 시각을 보관합니다. 다시 접속하면 복원 또는 삭제를 선택합니다. 새 글 등록 성공/로그아웃/계정 전환 시 지우며, 늦게 끝난 업로드가 다른 계정의 자산을 만들거나 참조하지 않도록 세션 계정을 재확인합니다. 업로드 전 원본 파일은 로컬 초안에 저장하지 않습니다. 기기 간 초안 동기화와 수정 중 초안 영속화는 제공하지 않습니다.

피드는 시각+ID 커서로 20개씩 읽습니다. 더 불러온 분량까지 포커스 복귀와 표시 중 15초마다 다시 조회하여 숨김/삭제를 반영합니다. 상세와 댓글도 같은 주기로 갱신하며 서버 RLS는 요청마다 즉시 검사합니다. 게시글 ID를 직접 열어도 숨김/삭제 본문을 얻을 수 없습니다. 댓글은 50개씩 페이지를 끝까지 읽고 부모-답글로 표시합니다. 대량 댓글의 점진적 렌더링은 후속 최적화 대상입니다.

삭제된 부모에 정상 답글이 있으면 `list_comments`만 본문·작성자·이미지가 null인 자리를 반환합니다. 답글은 남고, 정상 답글도 없으면 자리를 생략합니다. 기존 테이블 조회/RLS는 삭제 본문을 계속 숨깁니다. 댓글은 최대 1단계이고 부모와 게시글이 일치해야 합니다. 삭제한 부모에 새 답글은 추가하지 않습니다.

## 카테고리

`save_category`는 생성/이름/표시 순서를 변경하고 수정 버전을 검사합니다. `delete_category`는 모든 상태의 기존 글을 목적지로 옮긴 뒤 삭제하며 글 버전을 증가시켜 오래된 편집을 감지합니다. 마지막 카테고리는 삭제할 수 없습니다. 전용 guard 잠금으로 카테고리 변경과 게시글 저장이 경합해도 참조가 깨지지 않습니다. 운영자 권한은 서버에서 재검증합니다.

## 이미지와 무료 운영

`post-image`는 프로필과 같은 WASM 검증/변환 엔진을 사용하며 유료 Storage 변환을 호출하지 않습니다. JPEG/PNG/WebP, 10 MiB, 1,200만 화소, 각 변 8,192px 이하의 비애니메이션 입력만 받습니다. 서버는 EXIF 방향을 적용하고 메타데이터를 제거하여 긴 변 2,048px WebP와 256px 썸네일을 만들고 합계 5 MiB 이하로 제한합니다. 첨부 업로드 예약은 계정당 시간당 60개(실패 포함), 프로필은 기존 20개입니다.

1. JWT와 활성 회원 확인 후 `reserve_post_asset`가 pending 자산을 만듭니다.
2. 최대 크기를 확인한 원본을 private `temporary/<UUID>/source`에 저장합니다. 이 경로는 회원에게 조회 권한이 없습니다.
3. 파일 내용을 검증/재인코딩하고 `attachments/<UUID>/main.webp`, `thumb.webp`에 `upsert:false`로 저장합니다.
4. 임시 원본을 제거한 뒤 서버 전용 `finalize_post_asset`로 회원 상태를 재확인하고 ready로 확정합니다.
5. 글 저장 트랜잭션이 본인 소유/ready/첨부용 경로, 중복 없는 4장 이하 배열을 확인한 후 순서와 본문을 함께 확정합니다. 하나라도 실패하면 글과 첨부 변경을 모두 롤백합니다.

원본은 성공 시 남기지 않으며 실패 시 새 파일 제거를 시도합니다. 미참조 ready 이미지와 실패/중단 자산은 24시간 유예 후 정리할 수 있습니다. 프로필, 글/댓글 스냅샷, 첨부, 투표 스냅샷의 참조를 모두 검사하며 삭제/숨김 이력의 참조도 보수적으로 보존합니다. 이미지 참조와 정리 작업은 동일 자산 행 잠금에 참여합니다. 정리가 claimed 상태(`deleting`)로 바뀌면 새 첨부/프로필 연결이 불가능합니다. Storage 제거 실패 시 다음 실행에서 재시도하고 파일 삭제가 끝나야 메타데이터를 삭제합니다.

유예 시간이 지난 초안 이미지는 정리될 수 있습니다. 복원 후 첨부 오류가 나오면 이미지를 제거하고 다시 업로드합니다. 브라우저는 인증된 다운로드를 Blob URL로만 표시하며 화면 종료 시 URL을 폐기합니다. 영구 서명 URL은 저장하지 않습니다.

실제 클라우드 Deno/WASM 번들·무료 CPU/메모리 한도·SMTP·Pages는 아직 배포/검증하지 않았습니다. 로컬은 같은 함수를 Node HTTP 어댑터로 실행합니다. 클라우드는 `post-image`도 별도 배포하고 `APP_ORIGINS`를 설정해야 합니다.
