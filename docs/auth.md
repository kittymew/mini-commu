# 3단계 인증 흐름

2026-10-20 기준 Supabase Free에서 제공하는 Auth와 PostgreSQL RPC만 사용합니다. 별도 유료 인증·이미지 변환·상시 서버는 추가하지 않습니다. 무료 한도는 실제 사용량에 따라 관리하며 로컬 검증은 클라우드 할당량 검증을 대신하지 않습니다.

## 가입과 복귀

1. 가입 화면에 이메일, 8자 이상 비밀번호, 초대 코드를 입력합니다. Auth 계정만 생성되며 이때 코드는 소진하지 않습니다.
2. 기본 Supabase 인증 메일의 링크를 요청한 브라우저에서 엽니다. Auth가 이메일을 확인하고 사이트 기본 주소에 PKCE `code`를 붙여 돌려보냅니다.
3. 앱은 라우터 생성 전에 code를 메모리에 보관하고 주소를 `#/auth/callback`으로 즉시 정리합니다. 인증 버튼을 누르면 `exchangeCodeForSession`으로 한 번만 교환합니다. React Strict Mode의 중복 호출도 피합니다.
4. 회원 등록 전 계정은 초대 확인 화면으로 이동합니다. 서버가 이메일 인증·코드·요청 제한을 확인하고 가입과 사용량을 함께 확정합니다.
5. 활성 회원이 되면 캐릭터 안내로 이동합니다. 실제 캐릭터 생성 기능은 4단계입니다.

다른 브라우저에서는 PKCE verifier가 없어 자동 로그인 교환이 불가능합니다. 이메일 인증 자체가 완료됐다면 이메일/비밀번호로 로그인하고 초대 코드를 입력해 가입을 이어갑니다. 재발송은 해당 브라우저에서 새 PKCE 요청을 만듭니다. 가장 최근 요청한 메일 링크를 사용합니다. 정리된 콜백 화면을 새로고침해 code를 잃었다면 원래 메일 링크로 돌아가거나 메일을 재요청합니다. 인증 코드·토큰·초대 원문을 로그나 분석 이벤트에 추가하지 않습니다.

## 비밀번호 재설정

재설정 요청은 계정 존재 여부를 드러내지 않는 동일한 안내를 제공합니다. 요청한 브라우저에서 메일 링크를 열고 확인하면 Auth의 `PASSWORD_RECOVERY` 이벤트에 따라 새 비밀번호 화면으로 이동합니다. 요청자와 연결된 복구 상태는 sessionStorage에 보관하므로 같은 탭 새로고침으로 입력 화면을 잃지 않습니다. 비밀번호 확인 입력이 일치해야 변경합니다. 변경 후 모든 세션의 refresh 권한을 로그아웃 처리하고 새 비밀번호로 다시 로그인합니다. 이미 발급된 access token은 Auth의 만료 정책을 따릅니다.

이용 정지 계정도 비밀번호는 복구할 수 있지만 커뮤니티 접근은 계속 차단됩니다. 회원 활성화는 운영자만 수행합니다.

## 접근과 상태 정리

- 세션은 Supabase SDK가 저장·자동 갱신합니다. UI 상태는 서버의 사용자 확인과 회원 상태 조회 후 결정합니다.
- 비로그인은 로그인, 가입 미완료 계정은 초대 확인, 정지 계정은 정지 안내로 이동합니다.
- 회원 조회 오류 시 콘텐츠를 숨기고 다시 시도할 수 있습니다.
- 로그아웃은 현재 세션을 종료합니다. 비밀번호 복구 완료 시에는 전체 세션 종료를 요청합니다.
- 현재 앱에는 콘텐츠 캐시나 이미지 화면이 없습니다. 정리 로직과 테스트용 초안·이미지 키로 계정 정보가 남지 않음을 검증했습니다. 이후 실제 콘텐츠 구현에서도 이 경계를 다시 검증합니다.

## 로컬 검증과 외부 설정

`pnpm db:start --runtime native` → `pnpm db:migrate` → `pnpm test:auth` 순으로 실행합니다. 개발 서버가 5173 포트를 점유하고 있으면 먼저 종료합니다. 테스트는 실제 로컬 Auth·PostgreSQL·Mailpit을 사용하고, 계정/초대 준비와 정리에만 관리 권한을 사용합니다. 브라우저에는 공개 키만 전달합니다. 메일·비밀번호·토큰이 기록되지 않게 인증 테스트의 trace·스크린샷·동영상 수집을 끕니다. 네트워크 실패 시나리오만 브라우저 요청을 의도적으로 중단하며 성공 응답을 모킹하지 않습니다.

실제 서비스에는 Supabase URL, publishable key, 배포 기본 URL, Auth redirect 허용 목록과 외부 SMTP 설정이 필요합니다. 클라우드 연결·실제 메일 전송·Pages 배포는 이번 단계에서 실행하지 않았습니다. 기본 메일 템플릿을 유지합니다. native 로컬 런타임은 사용자 정의 메일 템플릿 제공을 지원하지 않으므로 이 기능에 의존하지 않습니다.
